## 0. 结论先行

1. **本机已跑通过"图/文 → 视频（含声音）"链路**：`D:\minimax-h3-demo` 项目 8/22~9/2 实测出过 **18 条 MiniMax H3 视频**（5.2s 与 15.1s、864×480@24fps、AAC 立体声），模型资产 ~64GB 全在位。
2. 三条候选路线：
   - **① MiniMax H3（首选试跑，零下载）**：单图首帧 I2V 工作流现成（9/2 更新、含 LoadImage、输出前缀 `video/MiniMax_H3`）；另有多图参考 R2V（≤9 图锁角色）与首尾帧插值、最长 15s、原生音频。
   - **② Wan2.2 A14B I2V（补料，单帧美学最强）**：umt5 编码器 + VAE 本机已有，仅需补双专家（GGUF ≈21GB）+ LightX2V 加速 LoRA；16GB 配方成熟。
   - **③ LTX-2.3 / LTX-Video（速度+原生音频）**：比 Wan 快 10–18×、原生竖屏；需 ~15–40GB 下载。
3. 云端（不占卡）：可灵 2.6 ¥0.3/秒起、HappyHorse ¥0.44/秒（720p）等；全本规模粗算 ¥3k–8k；建议"本地跑量 + 云端重点镜头"。
4. **待办**：一次 H3-I2V 冒烟复验（现行 ComfyUI 0.34.0 下）——按用户要求本轮未跑，等拍板。

## 2. 本地环境盘点（只读实测，2026-09-29）

- **算力**：RTX 5060 Ti 16GB（调研时正被慧铭训练占用 ~70%，单卡纪律）；ComfyUI 0.34.0 + torch 2.13.0+cu130；启动参数含 `--reserve-vram 2`；推理在 Windows 侧同机 ComfyUI（WSL 与 Windows 共享同一张卡）
- **视频节点已装**：ComfyUI-WanVideoWrapper（Kijai）、ComfyUI-VideoHelperSuite、ComfyUI-AnimateDiff-Evolved、帧插值/深度/姿态等
- **MiniMax H3 全套（~64GB）**：
  - `minimax_h3_fl2va_pruned_int8` 20GB（T2V / I2V 首帧 / 首尾帧）
  - `minimax_h3_ref2va_pruned_int8` 20GB（多参考 R2V：≤9 图 + 3 视频 + 3 音频）
  - Qwen3VL-32B 文本编码器（nvfp4_awq）15GB；视频 VAE 4.9GB；音频 VAE 0.6GB
  - Turbo LoRA：FL2V 8step v1.0 + Ref2V 4step v0.1（各 1.9GB）→ 4~8 步级加速
  - 能力：**最长 15s / 原生立体声（人声+音效+音乐一次生成）**；支持单图变视频、首尾帧、参考锁角色
- **Wan 家底**：umt5_xxl 编码器 ×2（11GB，含 comfy 转换版）、Wan2.1 VAE、Wan2.1 T2V 1.3B（软链）→ 补 Wan2.2 双专家即可出活

- **模板库 518 个**（comfy-cli 离线补丁）：MiniMax H3 官方模板（i2v / r2v / i2v_continuation / t2v）、Wan2.2 14B（i2v / flf2v / s2v / fun 系列）、LTX-2 / 2.3 / 2.5、混元 1.5 720p、Seedance2 分镜等；另有云 API 模板（可灵 2.6 / Seedance1.5 / HappyHorse / Grok / Gemini）
- **磁盘**：D: 299GB 可用；WSL 515GB 可用；WSL 侧有 ffmpeg 9.0.1（后期合成可用）

### 2.2 历史实证（最硬的证据）
- **18 条 MiniMax H3 出片**（8/22 01:13 ~ 9/2 23:15）：`ComfyUI/output/video/MiniMax_H3_00001~00016` + `MiniMax_H3_R2V_00001~00002`
- ffprobe 探针：#01 = 864×480 / 24fps / **5.167s** / AAC 立体声 32kHz；#16 = 同规格 / **15.083s**；R2V#01 = 同规格 5.167s
- 抽帧观感（辅助视觉模型描述）：人物特写与街景 = **写实电影感、清晰稳定**；强特效/巨物合成帧偏弱（糊、过曝）→ 叙事型镜头可用
- 工作流时间线佐证：t2v（8/22 建）→ r2v（8/26）→ **i2v 工作流 9/2 22:24 更新（含 LoadImage，输出前缀 `video/MiniMax_H3`）→ 当晚 22:45 / 23:01 连续出片 + 23:05 / 23:15 两条 R2V** ⇒ "配图当首帧"的本机管线是通着的
- 另有 AnimateDiff 产出 ×3（`animdiff_*_jiangnan`）、Wan T2V 产出 ×7——多条链路均有过实跑
- 结论：**这不是"能不能跑"的问题，而是"用哪套、跑多快、画质够不够"的问题**

### 2.3 缺口清单（走对应路线才补）
- H3 小显存优化档（仅当 20GB int8 在 16GB 上不顺时）：pruned Q4_K_M GGUF 10.6GB 或 nvfp4 11.7GB + TE Q2_K 7.9GB（即官方 12–16GB 推荐档）
- Wan2.2 双专家模型 + LightX2V 4 步 LoRA ×2（走 Wan 路线时，≈21GB 下载）
- LTX-2.3 系（走 LTX 路线时）：22B fp8 + gemma 文本编码器 + 蒸馏 LoRA + 空间放大 + 声码器（~40GB；或社区 Q4_K_M GGUF 压缩档）
- RIFE 帧插值模型（可选，24→48fps）；其余都用现有

## 3. 本地方案对比（16GB 卡口径）

### 3.0 三家直接对比（2026-08/09 网络同提示实测；修正单一「画质王」口径）

- **Floyo 8/7 对比**（同提示）：**H3 运动质量三家最佳**（相机自然、物理可信、快动作不散）；**Wan2.2 单帧最漂亮**（色彩/构图）但运动漂浮、背景常静止；LTX2.3 稳但僵硬
- **Floyo 9/17 对比**（LTX2.5/Wan2.2/H3，同参考图）：LTX 最快（~4 分钟/条）；Wan 帧最锐利；**H3 拿下 5 项评分中 3 项，「真要发生动作时最可靠」**
- **videcool rack-focus 实测**：H3 全项最佳（含对白音频）；LTX 拆成两镜/镜头指令失败；Wan 画错角色、无音频
- **发布日基准快照**：H3 视频编辑第 1；T2V 仅次于 Gemini Omni Flash；I2V 仅次于 Seedance 2.0 / Gemini Omni Flash（后两者为闭源云）
- ⚠️ 速度详情：LTX 最快为真、但「快 10–18×」是宣传口径——同场景实测（4090，5s/1080p）：LTX ≈25–40s vs Wan ≈90–120s（≈3×）。H3 单条更重但能打：RTX 3060 int8 5s/480p ≈3–4 min、10s ≈11 min；8GB 显存即可跑 480–600p；Turbo 4/8 步 + PDD 加速（20→10 步省 ~40%）→ 本机 16GB 预期分钟级/条。另有用户反映消费卡上 H3 比 LTX 更稳、更省显存（LTX 8GB 频报 OOM）
- **对 I2V 的推论**：首帧由我们自己提供 → Wan 的「单帧美学」优势被稀释，运动质量与「带声音/锁角色」权重更大 → H3 在本用途上很可能是「最合适」而非仅「最方便」

### 3.1 MiniMax H3 · I2V / R2V（推荐首试）
- **配方**：现有 int8 剪枝版 20GB 需分时装载/卸载（ComfyUI 自动 offload）；跑不顺 → 换 Q4_K_M GGUF
- **能力**：单图首帧、首尾帧、≤9 图参考锁角色、15s、自带声音
- **速度**：实测 RTX 3060 int8 单条 5s/480p ≈3–4 min；本机历史同呈"分钟级/条"（未计时）；16GB 预期分钟级，准数需冒烟实测
- **优势**：零下载、管线现成、唯一"视频+声音一次出"、R2V 可把定妆图锁成角色
- **劣势**：历史成色 480p 档（864×480）；强特效镜弱；16GB 下速度待测

### 3.2 Wan2.2 A14B I2V（单帧美学天花板，需补料）
- **配方（16GB 成熟方案）**：双专家 GGUF Q4_K_S ×2（各 ~10.6GB）+ LightX2V 4 步 LoRA；832×480×81 帧=5s（13–14GB 显存）；720p 顶格（15–16GB）；ModelSamplingSD3 shift≈8.0
- **速度参考**：4090 约 4m20s / 5s 片；5060 Ti 预计 2–3 倍（约 10–15 分钟/条，估算）
- **优势**：单帧锐度/色彩口碑第一（无声；⚠️ 2026-08 起含 H3 的同提示对比显示运动质量 H3 更佳）；补料最少（编码器/VAE 已有）
- **劣势**：单条慢；无音频

### 3.3 LTX-2.3（速度+音频新贵）
- 22B；16GB 走 Q4_K_M GGUF / 蒸馏版；**速度三者最快**（4090 单条 5s/1080p ≈25–40s）但 8GB 卡频报 OOM、内存占用被吐槽；原生 9:16 竖屏；单次生成即带同步音频；许可：年营收 <$10M 免费档
- **劣势**：全量下载大（~40GB）；偶发"飘"的运动质感

### 3.4 AnimateDiff（存量复古选项）
- 现成可跑（有 jiangnan 历史产出）但质量代差明显；适合风格化循环小动图，不推荐正片

### 3.5 一句话选型
**先 H3（0 成本试；且对比证据支持它在 I2V 上最合适）→ 单帧极锐需求再补 Wan2.2 → 追速度补 LTX-2.3**；三者共用同一套 ComfyUI 与调度纪律。（I2V 场景「首帧由我们提供」，Wan 的单帧美学优势被稀释；运动质量权重更大）

## 5. 成本 × 规模 粗算（含 1.5~2× 返工系数）

- 全本口径：237 章 × 5~8 图 ≈ **1400 张**
- **纯本地（H3/Wan）**：~1400 条 × 分钟级 = 数十~两百 GPU 小时（分多天排班；与出图/训练抢卡 → 排程问题，不是钱的问题）
- **纯云**：5s/条 × ¥1.5（Kling2.6 720p）≈ ¥2100 → ×返工 ≈ **¥3k–4k**；Kling 3.0 档 ≈ ¥6k–8k；HappyHorse ≈ ¥3k–6k
- **混合推荐**：每章 1–3 个重点镜头走云 + 其余微动效/本地 → 云成本可压到 **¥500–2000 量级**起步

## 6. 风险与坑（诚实版）

1. **一致性**：I2V 从 LoRA 出的图出发 = 首帧即锚定角色；风险在运动大时人物漂移 → 短镜头（≤5s）+ 小运动 + R2V 辅助
2. **背景纹理抖动**：I2V 行业通病（教程普遍吐槽）；可用后期稳定化缓解
3. **H3 现状未复验**：8 月成功 ≠ 0.34.0 下必然成功（大概率可以）；需一次冒烟
4. **单卡纪律**：视频生成与 LoRA 训练、章节出图三者互斥——统一排程
5. **音频默认不开**：H3 能带声，但"只做图不碰音频"是既有纪律——视频是否带声音由用户拍板
6. **云返工成本**：AI 视频"抽卡"属性强，预算按 1.5~2× 成功率算
7. **合规**：发行到平台需注意 AI 生成内容标注要求（真要发布时再细化）
